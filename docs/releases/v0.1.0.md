# InfraBadge CASA v0.1.0

Primera release oficial de InfraBadge CASA. Código original bajo **Apache-2.0**;
[LICENSE](../../LICENSE), [NOTICE](../../NOTICE) y
[licencias/atribuciones de terceros](../../THIRD_PARTY.md).
La release se etiqueta sobre el commit definitivo de main con CI aprobada,
conservando el runtime y el firmware físico instalados.

## Arquitectura

ESP32-S3 Waveshare e-paper1.54 V2 → HTTPS8443 Edge CASA permanente en
infrabadge-core → HTTPS9443 Core con SQLite. Tres nodos reales: Core, nas-01 y
Fedora; collectors con identidades independientes. Fedora no es intermediaria
entre el badge y CASA. No hay dependencia de un edge portátil para uso diario.

## Funcionalidades verificadas

- Firmware M3.6 diurno, resumen y detalle de nodos reales, navegación BOOT,
  pantalla200×200, SHTC3 y periféricos básicos validados en sus etapas previas.
- HTTPS con CA/SAN/fechas y credenciales separadas; contrato v2, TTL, ETag200/304
  y consulta autónoma. Framebuffer diff y deep sleep conservados.
- Supervisión TLS instalada, monitor/evaluate/renew activos, monitor histórico
  deshabilitado. Custodia aislada de la misma CA y rollback real de instalación
  con restauración exacta. Verificador público bajo sandbox real comprobado.
- Regresión local de cierre:599 tests Python PASS, Ruff y C con ASan/UBSan;
  CI conserva nueve perfiles ESP-IDF5.5.5 y ARM64/x86_64. Consultar resultados
  exactos del PR12 y del merge: CI no equivale a nueva validación física.

## Límites y pendientes aceptados

- **Primera rotación real del leaf pendiente** del27/10/2026 a22:03:10 ART;
  certificado actual hasta06/11/2026 a22:03:10 ART. No se fuerza antes del umbral.
  Rollback de instalación no acredita rollback del primer leaf productivo.
- Tres fallos transitorios del collector recuperados; causa desconocida. Observar
  recurrencias sin atribuir causa ni cambiar políticas por este cierre.
- Noche opcional00–08 ART deshabilitada; prueba física pendiente. TRABAJO ausente.
- Caducidad/recuperación física M3.6 inconclusa; no se declara validada por los
  ensayos de etapas anteriores. Energía y autonomía400mAh aún sin caracterizar.
- OTA, audio, micrófono y periféricos adicionales diferidos. Sin pantalla táctil.
- Notificación externa no habilitada. Guardias transitorias no sobreviven reboot;
  recuperación automática al arrancar y estabilidad prolongada no acreditadas.
- Vigencia de CA independiente, hasta21/01/2027 a22:03 ART; renovar leaf no la extiende.

El runtime TLS productivo conserva bd4a98a y dos complementos operativos de
inventario autorizados por separado. Este merge documental no los sustituye,
no reinstala servicios, no cambia certificados y no interviene firmware/NVS.
Backups y configuraciones recuperables permanecen privados; no forman parte de
los assets de release ni de CI. [Estado y rollback](../TLS-DEPLOYMENT.md).

## Alcance de la distribución

El ESP32 conserva el firmware M3.6 diurno físicamente validado; esta publicación
**no lo reflashea** ni cambia NVS. Los artefactos de compilación de CI corresponden
a su SHA y entorno de build: no se deben identificar como el binario instalado
ni como una nueva validación física del hardware.

Esta release distribuye el código fuente del tag mediante los archivos de fuente
generados por GitHub. No adjunta binarios adicionales, imágenes de contenedores,
backups, certificados, claves, tokens, configuraciones privadas ni logs.
ESP-IDF y paquetes Python se obtienen por separado con los commits/locks fijados;
no se relicencian bajo Apache-2.0 ni se incluyen sus binarios en esta release.
La adopción de licencia y documentación no cambia funcionalidades o servicios.
