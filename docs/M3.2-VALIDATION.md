# M3.2 — evidencia y pendientes

Base main `df11e98`, M3.1/PR5 sin mezclar. Esta página registra software; la
[validación de hosts](M3.2-PHYSICAL-VALIDATION.md) del piloto se clasifica aparte.
La consolidación no contactó hosts, cambió redes o accedió a la placa.

## SOFTWARE VALIDATED — ejecutado localmente

- Base b2ae0de:268 tests Python,199 regresiones M3 y69 casos M3.2; la
  consolidación añade14 regresiones nativas,282 en total. Incluyen múltiples
  collectors/duplicados concurrentes, scopes de sitio/rol/edge, CPU sostenida,
  caducidad/OFFLINE/recuperación y suspensión simulada por gap.
- SQLite: transacciones/rollback sin ACK falso, migraciones1→2, versión futura,
  corrupción, symlink, exclusión de writer, retención/watermark, clock rollback,
  backup mientras writer trabaja y restore histórico/revisión monotónica.
- Edge: TLS real localhost en dos saltos con CA explícita;200/304, CA ajena,
  upstream vencido/SAN incorrecto, pérdida y recuperación de transporte simuladas,
  redirects/oversize/contrato incorrecto/roles/rutas rechazados.
- Collector: sensor ARM `cpu_thermal` explícito, sensor ausente/inválido, dos
  entregas de mismos bytes con un deadline y ausencia de retry TLS/timeout/HTTP.
- Ruff/formato, fixtures y protocolo M2/M3, plantilla vacía segura y generador
  Quadlet dry-run. Resultados exactos por revisión se consultan en el PR.
- OSV detectó dos alias del aviso certifi heredado y se corrigió a2026.10.19,
  validando el lock en un venv nuevo. La consulta posterior de25 versiones no
  devolvió avisos OSV; no cubre SO/SDK/stdlib ni se actualizó M3 operativo.

Las14 regresiones consolidan dos FDs TLS/Store, scopes, exclusión del segundo
writer, rechazo de sockets incorrectos, credenciales propias0600 y rechazo
por mínimo de intervalo tras restart. No prueban la causa HTTP histórica.
Se verifican además cuatro unidades nativas temporales y el lock runtime.

El warning de TestClient heredado se conserva como deuda, no fallo ocultado.
Fallos intermedios de imports/lifespan del fixture edge se corrigieron; el cliente
HTTPS se cierra en el event loop que lo creó. No se presenta un intento fallido
como PASS ni se atribuyen pruebas de loopback a Tailscale físico.
