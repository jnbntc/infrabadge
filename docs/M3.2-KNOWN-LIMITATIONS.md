# M3.2 — limitaciones conocidas y deuda aceptada

Estas limitaciones delimitan afirmaciones de producción; no crean nuevos
bloqueos del piloto funcional aceptado o de integrar su software. No se cambian
hosts para resolverlas durante la consolidación.

| Área | Límite y tratamiento |
| --- | --- |
| Incidencia transitoria | Causa no confirmada; rearmado temprano es hipótesis respaldada. Recuperación no equivale a RCA resuelta; [diagnóstico](M3.2-COLLECTOR-INCIDENT.md) |
| Memoria del central | Arranque con cgroup_disable=memory. MemoryMax declarado no efectivo. LimitAS limita espacio virtual por proceso; no reserva ni cap de RAM física compartida |
| Memoria remota | Se observó memory.max64MiB para el collector. No extrapolar al central ni a otros hosts |
| CPU | Controlador disponible no implica CPUQuota aplicado. Las unidades nativas no fijan una cuota; porcentajes son muestras cortas, no máximos |
| Energía y medio | Fuente/temperatura/desgaste no caracterizados a largo plazo. Sin corte de energía, ensayo destructivo o garantía24/7 |
| Copias y DR | Backup externo validado, segunda microSD y disaster recovery pospuestos por el operador. Copias en la misma tarjeta y restore en RAM no cubren pérdida física |
| Reinicios | Restart del gateway probado; reboot completo de la ampliación de dos nodos no realizado |
| TLS | Hoja final observada vence20/01/2027 04:24:17 UTC; renovación/custodia requieren operación aprobada. Sin auto-renew instalado por esta consolidación |
| Grants | Firewall restringe9443 del central; política administrativa Tailscale sigue amplia y no se alteró. No afirmar aislamiento de tailnet completo |
| Edge LAN | Guard de interfaz/perfil/DNS/ruta/lease M3.1 todavía no portado. Template de edge no es aprobación de exposición; gate previo a cualquier despliegue |
| Inventario/sensores | Un FS por collector; remoto mide raíz del SO, no SMART/espacio de discos de datos. Temperatura sólo de sensor identificado |
| Central único | Sin HA ni réplica. Pérdida de Tailscale/core no se convierte en fallo crítico físico del nodo |
| Persistencia | Un writer; locks y fsync dependen del medio. Retención acotada, sin downgrade automático. Backup antiguo pierde watermarks posteriores |
| Secretos | Archivos privados y scopes, sin cifrado propio de SQLite/NVS ni defensa frente a administrador/host comprometido |
| Observabilidad | Error collector genérico oculta HTTP/causa concreta; se conserva por privacidad. No inferir código de respuesta a partir de coincidencia temporal |
| Evidencia | Capturas de hosts hasta22/10/2026 05:07:45 UTC; no monitoreo continuo ni lectura remota en esta revisión |
| Dispositivo | M3.2 sin nueva prueba ESP32, LAN, navegación multisitio o consumo. No cambia firmware, NVS ni planes físicos consumidos |
| Pipeline | Warning heredado TestClient y acciones antiguas de Node20 forzadas a Node24; no se ocultan ni se confunden con fallos de aplicación |

La diferencia entre [MemoryMax](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html)
y [RLIMIT_AS](https://docs.python.org/3/library/resource.html#resource.RLIMIT_AS)
es material: no describir el segundo como fallback equivalente de RAM. Habilitar
el controlador implicaría revisar arranque/reboot con autorización aparte; no se
hace para convertir una declaración de unidad en un PASS.

Si se pierde frescura, mostrar UNKNOWN/OFFLINE según horizonte; nunca renovar
por GET/duplicado ni usar una copia restaurada como actual. Ante DB corrupta,
preservarla, detener sólo componentes nuevos según aprobación y tratar el caso
como incidente distinto; no restaurar silenciosamente una DB antigua.

La evolución priorizada y sus autorizaciones están en el
[roadmap](ROADMAP-M3.3-M3.5.md); el alcance real en
[PHYSICAL-VALIDATION](M3.2-PHYSICAL-VALIDATION.md). Ninguna deuda autoriza cambios
automáticos, exposición de puertos, pruebas sobre servidores laborales o flasheo.
