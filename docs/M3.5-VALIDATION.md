## Reproducción sin abrir puertos

Usar un venv aislado y las dependencias fijadas existentes; no SDK pip o paquetes
globales. El generador de imágenes sólo requiere Python estándar.

```sh
python3 -m venv /tmp/infrabadge-m35-tests
/tmp/infrabadge-m35-tests/bin/python -m pip install --require-hashes \
  -r gateway/requirements.lock -r tools/m3/style.lock
/tmp/infrabadge-m35-tests/bin/python tools/m35/check_offline.py
python3 tools/m35/preview.py --check
/tmp/infrabadge-m35-tests/bin/python tools/m2/generate_protocol.py --check
/tmp/infrabadge-m35-tests/bin/python tools/m3/generate_fixtures.py --check
PATH=/tmp/infrabadge-m35-tests/bin:$PATH bash tools/m3/check_style.sh
```

`check_offline.py` instala un audit hook sólo en ese proceso para rechazar
socket.bind/connect/getaddrinfo; no cambia firewall, proxy, DNS o servicios.
Excluye explícitamente15 casos TLS/socket existentes, incluido el test que
arranca un hijo con dos FDs. La CLI `--help` del paquete collector corre en un
hijo aislado conocido, sin red; el hook no es un sandbox general de procesos hijos.
La integración nueva usa ASGI/MockTransport, sin listener. No confundir su URL
https sintética con handshake TLS real.

La primera exploración del runner detectó tres variantes TLS de observer no
incluidas en las exclusiones: el hook rechazó bind ANTES de abrir el puerto.
Se completó la lista explícita y la ejecución final pasó. Otro test de auditoría
se corrigió para reconocer dígitos en nombres de macro I2C; no fue un fallo GPIO
ni se modificó el HAL. Una etiqueta no soportada se cambió a texto de la fuente
M1, sin agregar glyphs o dependencias.

## CI y firmware

Los tests nuevos forman parte de `pytest.ini`; la verificación visual se ejecuta
en el test de referencias. `tools/m3/check_style.sh` incluye tools/m35 y tests/m35.
El workflow existente conserva regresiones completas, TLS real en runners aislados
AMD64/ARM64 y siete perfiles ESP-IDF, sin hardware. No se eliminaron esos tests
ni se cambió la CI para ocultarlos: sólo se omiten en el runner local sin puertos.

Esta rama se prepara localmente; **no se ejecutó CI remota ni se reconstruyeron
los siete perfiles durante esta tarea**. No heredar checks de main/PR7 como
validación del SHA nuevo. Antes de incorporar firmware se exigirán build de los
siete perfiles, C/ASan/UBSan y revisión del contrato C, además de CI sobre el
commit propuesto. No se instaló compilador/SDK en Fedora para esta preparación.
