# Despliegue preparado, NO ejecutado

Antes de cualquier intervención: autorización de cada host/sitio y aprobación
organizacional TRABAJO. No usar lanzadores ni provisiones consumidas de M3.5.

1. Inspección de sólo lectura autorizada del candidato: arquitectura/SO/runtime,
   recursos, actualizaciones, listeners, firewall, LAN, DNS y retorno por VPN.
   Confirmar si NAS puede alojar otro servicio sin perjudicar sus funciones.
   No deducir la situación vigente del reporte de21/10. En TRABAJO no elegir
   host final ni exportar datos sin su responsable.
2. Preparar unidad/imagen fijada no root, config privada0700/0600, CA explícita y
   hoja SAN correspondiente al DNS aprobado. Reutilizar plantilla
   `deploy/m32`/edge M3.5; no reemplazar servicios existentes. Conservar hash de
   imagen, unidades/config/identidades previas y backup consistente de SQLite
   con restauración separada comprobada si se cambia configuración Core.
3. Con autorización separada: crear scopes de edge CASA/TRABAJO, conectividad
   exacta edge→Core9443 y badge→edge8443. Presentar reglas por interfaz/origen y
   retorno TCP; no wildcard, reglas generales de VPN ni publicación a Internet.
   Armar rollback independiente con plazo antes de exponer listeners. No asumir
   que existe conflicto/firewall permisivo o que hay que cambiar Tailscale.
4. Validar desde cliente LAN autorizado: cadena/SAN/fecha,200/304 sin extender
   TTL, roles/scopes, revocación aislada y caída/recuperación del Core. Renovar
   leaf con la misma CA/SAN conserva confianza; rotar CA/URL/token exige paquete
   nuevo. No copiar CA privada al badge ni credenciales de collectors.
5. Preparar bundle privado1–2 bindings y configuración pública separada. Todos
   los bindings conservan device_id; cada seed_utc debe coincidir y proceder de
   host sincronizado justo antes de provisión. Sin SSID/token en argv/logs.
   Verificar tamaño/espacio NVS sin borrar claves, y conservar archivo privado
   normal M3.5. `ib_m2` no se migra ni sobrescribe.
6. Sólo con nueva autorización: verificar app/hash/tabla/offset e instalar
   únicamente app0x10000; nunca `idf.py flash`/flash_args porque incluyen tabla y
   bootloader. Sin erase_flash/eFuses/seguridad irreversible. En ventana fría10s,
   enviar una vez el nuevo paquete IBPROV36 y registrar ACK sin exponer payload.
   Esta iteración sólo genera paquetes offline, no incluye ejecución automática.
7. Probar CASA→pérdida→TRABAJO→CASA sin provisión adicional, ETag, caducidad,
   Wi-Fi perdido, CA/nombre/fecha/token erróneos, Core caído y recuperación.
   No cambiar red de producción para inducir fallos; usar laboratorio aprobado.
   Mantener cerrado USB para observar autonomía; distinguir causa exacta de wake
   de metadatos HTTP. Prueba nocturna según NIGHT-MODE, energía diferida.

## Comandos de preparación software

En el repo y entorno fijado:

```sh
bash tools/build-m36.sh --all
python -m pytest -c pytest.ini
bash tools/m3/check_style.sh
python tools/m36/visual.py --check
# Sólo preparar un archivo offline600 dentro de carpeta700; NO envía a USB:
python tools/m36/prepare_packet.py --config /ruta/privada/bundle.json \
  --output /ruta/privada/provision.packet
```

La herramienta usa el parser C compilado `results/m36-native/policy`, rechaza
archivos de entrada no privados/symlinks, duplicados y salidas existentes. No
actualiza ni certifica automáticamente UTC: preparar semilla fresca desde un host
con hora confiable y no reutilizar un paquete antiguo. Los ejemplos `.test` y
fixtures sintéticos no son certificados ni redes utilizables en producción.

## Rollback sin pérdida de datos

Desactivar sólo los servicios/exposición nuevos mediante restauración exacta
independiente; no parar collectors/Core existentes. Volver a imagen/config
anteriores, revocar sólo identidades de la prueba y no restaurar una SQLite vieja
sobre muestras nuevas. Conservar namespace nuevo para diagnóstico privado;
app M3.5 lee de nuevo ib_m2 intacto. Volver a app requiere autorización propia,
con binario/hash/offset verificados y sólo esa aplicación. NVS normal no se
revierte mediante app ni se borra partición. Backup privado8MiB sigue intacto.
Ninguna acción de estos pasos fue ejecutada en esta preparación.
