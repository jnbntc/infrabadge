# M3.2 — contrato de inventario

`distributed.config.CoreConfig` valida estrictamente config privada. Límites:
16 sitios,64 nodos activos/configurados,64 collectors,16 dispositivos/readers/
edges por rol; IDs lógicos ASCII de hasta32 caracteres. No descubrimiento ni
inventario de hardware, IP, MAC, usuarios o dominios. El ejemplo público contiene
sólo sitios home/work/mobile deshabilitados y cero nodos/credenciales.

El inventario de operación se mantiene **fuera de Git**. El piloto habilitó
únicamente dos roles domésticos, con métricas reales y credenciales propias;
los demás candidatos siguen fuera de ese alcance. El ejemplo público permanece
vacío/deshabilitado, sin direcciones o secretos. Es inventario declarado por
el operador, no prueba de existencia, arquitectura, sistema o conectividad remota.
No se publica su correspondencia con equipos reales. Trabajo exige autorización
organizacional antes de habilitar recolección/exportación.

`GET /api/v1/sites/{site_id}/nodes` requiere reader con ese sitio. Devuelve:

| Campo por nodo | Semántica |
| --- | --- |
| site_id / node_id / node_type | Asignación del servidor; tipo linux/gateway/mobile |
| enabled | Nodo y sitio habilitados; false excluye agregación e ingreso |
| last_seen | UTC de última recepción válida nueva, no hora de GET/duplicado |
| status | HEALTHY/WARNING/CRITICAL/UNKNOWN/OFFLINE según política |
| metrics | Metrics M3 sólo si pertenece a esta sesión y no venció TTL |
| historical_metrics | Última muestra etiquetada, sólo cuando metrics es null |
| freshness | fresh/never/stale/restored/disabled |
| age_seconds | Edad de collected_at; null sin muestra |
| health_policy | Policy M3 del servidor, no del collector |

Los modelos `NodeView`/`SiteView` impiden etiquetar como actual un histórico. El
payload conserva CPU, RAM, disco lógico, temperatura nullable, uptime y UTC de M3.
Sensor ausente/desconocido no se convierte en una temperatura inventada. Defaults:
TTL180s, min intervalo30s, CPU3 muestras, recuperación2, horizonte offline600s.
Temperatura sin umbrales implícitos.

Collector→nodo es1:1 con credencial independiente; IDs de nodo son globalmente
únicos, incluso entre sitios. Lectores/dispositivos sólo ven scopes explícitos.
Reasignar un nodo existente a otro sitio se rechaza: exige migración offline
revisada y política de históricos/credenciales, evitando fuga cruzada de datos.
Retirar una definición no elimina automáticamente su watermark/histórico privado.

No hay API de administración remota. Para migrar inventario: backup, editar config
privada, validar modelo y autorizar reinicio controlado. Configuración M3 previa
no se interpreta silenciosamente como M3.2; requiere mapeo explícito a sitios/roles.
